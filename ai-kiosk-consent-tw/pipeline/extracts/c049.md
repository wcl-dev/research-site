# c049: 智取櫃人臉辨識取餐完整指南:原理、準確率、應用場景 2026

## Directly addresses
- Q1a (區分計算): 銓幻元 MCS 智取櫃屬 B 區身分比對,Drafter 在 Q1a 量化時 must NOT 算進 A 區。
- Q4 / 概念區分: 「比對既有資料庫 (B 區)」vs 「不必比對既有資料庫 (A 區)」此關鍵技術差異的最 clean 例證。

## Key passages

### Passage 1 — for Q1a 區分 B vs A 計算
> 「與資料庫中的特徵向量進行相似度比對（<50ms）相似度超過閾值（99%+）→ 自動開啟對應格位」

**Page/section**: MCS 系統運作段落 (WebFetch 摘錄)
**Why it matters**: **B 區身分比對的最清晰技術定義**:有資料庫、有相似度閾值 (99%+)、有 1:1 識別目標 (對應格位)。**與 A 區 demographic inference 三個關鍵差異**:(a) B 區必須「與資料庫比對」、A 區「不必比對既有身分庫,可純 edge 分類」;(b) B 區目的是 identify 個人 (取對的餐) 、A 區目的是 categorise 群族 (推薦對的劇本/酒款);(c) B 區同意路徑通常在會員註冊端 explicit、A 區「站到 kiosk 前就被掃描」根本沒有 explicit consent opportunity。Drafter 在 Q1a 量化部署時必須兩軌分開列舉:A 區 (WiXtar 雙月 + 星益欣金色三麥 + ... ) vs B 區 (銓幻元 MCS + 頂呱呱 c048 + ...) 各自獨立計算。

### Passage 2 — for Q1a 部署場景 (B 區典型應用)
> 「企業員工餐廳...員工每天使用同一設備」「工廠宿舍 24H 取餐站...工人雙手可能油污或帶手套」「校園食堂自助取餐...學生每天使用」

**Page/section**: MCS 部署場景段落 (WebFetch 摘錄)
**Why it matters**: B 區典型部署場景:**封閉用戶群 (員工/工人/學生) + 高頻使用 + 固定場域**。對映個資法 §6 / §8 在 employment context 的特殊路徑 (參 c094 勞基法生物特徵出勤紀錄判決) — B 區的法律論證已有部分判例支持。**A 區 (餐飲消費者) 的法律論證全新且空白** — Drafter 在 Q5 / Q6 對照時可指出:B 區因為封閉用戶群 + 預先註冊流程,同意路徑可建構;A 區因為開放消費者群 + 即時無預警掃描,**同意路徑在當前 framing 下根本沒有 implementable 設計**。

## Structural content worth knowing
- MCS 部署場景全為「封閉/重複用戶」(員工餐廳 / 工廠宿舍 / 校園食堂),與本研究核心場景「開放消費者餐廳」(雙月 / 金色三麥) 屬不同 user model — Drafter 不應把 MCS 場景對應到雙月/金色三麥的法律分析。
- 「99%+ 相似度閾值」是 B 區技術門檻典型值;A 區的 demographic inference 不會有「99% 閾值」表達 (因為 inference 是 multi-class probability 分類非 1:1 match),這個技術 wording 差別本身就是 A/B 區辨識的 quick check。
- 「<50ms」是 MCS 推論延遲;與 demographic inference 「kiosk 前一瞬間就掃描」的時間軸都是 sub-second 量級,**消費者感知端無法區分 A 區 vs B 區** — 此「消費者感知無法區分但法律屬性差異巨大」是 brief A∩D 灰區的根源之一,Drafter 在 Q4 可指出。
- 全篇與 A 區無關,故 D 軸 (告知/同意) 對應 B 區 (會員預註冊) 路徑,不應作為 A 區 D 軸缺席的反例。

## Caveats / limitations

- 銓幻元 MCS 是否也提供 A 區 demographic inference 模組未明 — vendor 業務範圍可能跨 A/B 區,Drafter 引用時要 strictly only 引 B 區描述部分。
