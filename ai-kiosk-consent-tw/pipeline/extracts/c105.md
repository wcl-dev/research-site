# c105: 新北市消費爭議第 1 次申訴案件群組分析 (opendata dataset_id=124152)

**URL**: https://data.gov.tw/dataset/124152 (CSV: https://data.ntpc.gov.tw/api/datasets/bb4cefbd-dbdd-44a6-8734-a90a9e925cdc/csv/file)
**Source type**: 政府開放資料集 (新北市政府 — opendata) | **Quality**: qs=3
**Deep-read on**: 2026-05-27 (twinkle-hub MCP 503 → 直接 CSV API + manual CSV analysis)
**Access status**: ok (data.gov.tw landing page) + ok (CSV API direct download)
**Pages/length**: 12 列 (103-114 年縱貫) × 20 欄

## Directly addresses
- Q6 (執法/申訴實況 — quantitative 結構性零): 新北市 12 年 consumer complaint schema 全無 biometric/個資/隱私/inference category — Q6 結構性零的官方申訴統計層證據。
- Q4 (法律屬性 — A∩D 灰區 institutional invisibility): 即使消費者就 A∩D 灰區投訴,被歸入 "其他" residual bucket — 無 visibility 在官方統計層。
- Q7 (政策建議): 申訴 schema 改革是 Drafter 政策建議節可指出的 implementable 改革點 — PDPC 籌備處可請消保處新增 biometric/inference 子類。

## Key passages

### Passage 1 — for Q6 (schema 結構,12 年無變化)
> 「year,food_quantity,houses_quantity,cars_quantity,appliances_quantity,medical_quantity,energy_quantity,education_quantity,business_others_quantity,commodity_sum_quantity,tutorials_quantity,financial_insurance_quantity,transport_newsletter_quantity,leisure_travel_quantity,fitness_beauty_quantity,online_game_quantity,intermediary_services_quantity,interior_decor_quantity,services_others_quantity,services_sum_quantity」 (csv header)
>
> 「103,254,313,253,951,93,38,454,714,3070,309,129,892,162,452,482,252,68,432,3178」 (103 年第一列數據)

**Page/section**: CSV API direct dump verbatim (2026-05-27)
**Why it matters**: **新北市 consumer complaint schema 12 年 (103-114) 一字未改 — 18 個 substantive categories + 2 個 sum,全為傳統商品/服務分類**。**no biometric / 人臉 / 個資 / 隱私 / inference / kiosk / 餐飲 / AI 相關 category 存在**。 Drafter 在 Q6 可寫:**這是「結構性 invisibility」而非「無投訴」— 即使消費者就 WiXtar / 星益欣 / 雙月 / 金色三麥 kiosk inference 投訴,只能歸入 "商品類別其他 (business_others_quantity)" 或 "服務類別其他 (services_others_quantity)" — 兩個 opaque buckets 在 113 年 (2024) 合計為 714 + 432 = 1,146 件 (約 20% of total 6,248) — 即使全部都是 biometric inference 投訴(極不可能),仍無法獨立計算**。

### Passage 2 — for Q6 / Q4 (Schema 改革空間)
> 「services_others_quantity」 — 在 113 年 (2024) 為 2,235 件 / 105 年 (2016) 為 444 件 (5 倍成長);「business_others_quantity」 — 在 113 年為 3,074 件 / 103 年為 714 件 (4.3 倍成長)
> (analysis from full 103-114 年 CSV time series, columns business_others_quantity + services_others_quantity)

**Page/section**: CSV time-series 跨年數據分析
**Why it matters**: **「其他」residual buckets 的數量遠超專屬 categories,且 10 年成長 4-5 倍**。 — 對 Drafter Q4 / Q6 / Q7 政策建議重要:**residual bucket 成長表示 "新類型 consumer complaint" 正在快速出現,但 schema 未跟上**。AI Kiosk demographic inference 投訴 (若存在) 完全落入此 residual,**即使 PDPC 想計算 enforcement 需求,沒有官方數據可基**。Drafter 可建議:**消保處更新申訴分類 schema,新增「生物特徵 / inference / 自動化決策」獨立 category;對應個資法新增告知 / 同意義務監管後,enforcement 才有 visibility 基礎**。

### Passage 3 — for Q6 (申訴量基準參照)
> 113 年 (2024) services_sum_quantity = 8,500 件,commodity_sum_quantity = 7,153 件,**total 15,653 件**;103 年 (2014) total 6,248 件 — **10 年總申訴量增 2.5 倍**

**Page/section**: CSV 103-114 年 total trend
**Why it matters**: 新北市 consumer complaint 從 103 年 6,248 件成長到 113 年 15,653 件 (2.5 倍),**整體基數大量增加但 schema 未細分** — 對 Drafter 「司法零 + 申訴零」找原因時可指出:**問題不是「沒人投訴」而是「投訴系統 categories 不能 detect」**。15,653 件中可能含 biometric inference 投訴,但被歸入 5,309 件 residual bucket 中,**Q6 的「執法零」結論在數量基數大的背景下更尖銳**。

## Structural content worth knowing
- 新北市 dataset 涵蓋 103-114 年 (2014-2025) 12 年縱貫,**schema 未變化** — 對 Drafter 重要:**官方申訴分類系統十年無更新,意味 AI / inference / biometric 等新類型 consumer harm 完全缺 visibility framework**。
- "申訴及調解程序" 拆 3 軸 (第一次申訴 / 消保官申訴 / 調解案件) — 113 年新北市第一次申訴 3,612 件 + 消保官 758 件 + 調解 194 件 = 合計 4,564 件 (Taoyuan 數;新北市對應拆軸格式可能類似)。
- "其他" bucket 在多年呈現大量複合性 — 是長期未細分的隱藏池。
- 申訴 schema 改革沒有立法限制 — 屬消保處內部 operational decision;Drafter 在政策建議節可提:**新增 "生物特徵蒐集 / inference 自動化決策" 子類,所需 cost 極低、benefit 為 Q6 量化的 enabler**。

## Caveats / limitations
- 「結構性零」不等於「實質零」 — 不能直接結論「新北市無 biometric 投訴」,只能結論「新北市 schema 不能辨識 biometric 投訴」。
- "business_others" / "services_others" 兩個 residual buckets 的詳細案件描述未公開 — 無法 verify 多少屬 biometric 相關。
- 此 dataset 為新北市 only,**全國總申訴量需綜合其他縣市 + 消保處全國統計**;Drafter 在 Q6 結論可借此 dataset 作 schema 結構性 finding,不應推論全國數量。
- twinkle-hub MCP 503 阻擋本應該的 query — 改以 CSV API direct download 達到等效 deep-read;但若 operator 後續想 query 跨縣市跨年聚合 (例如「全台 12 年 services_others 趨勢」) 仍需 twinkle-hub 恢復或自寫 ETL。
- 部分縣市 (台中 dataset 88043) JSON API 路徑為 newdatacenter.taichung.gov.tw,DNS lookup failure (proxy 問題),無法 deep-read;Drafter 若需擴展 Q6 多縣市覆蓋可請 operator 救援。
