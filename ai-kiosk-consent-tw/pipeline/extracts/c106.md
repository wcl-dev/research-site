# c106: 桃園市政府每年度消費爭議申訴案及調解案商品類型分析表 (opendata dataset_id=149422)

**URL**: https://data.gov.tw/dataset/149422 (CSV: https://opendata.tycg.gov.tw/api/dataset/782a2aed-8f19-4604-8036-40db53fc5fd1/resource/...)
**Source type**: 政府開放資料集 (桃園市政府 — opendata) | **Quality**: qs=3
**Deep-read on**: 2026-05-27 (twinkle-hub MCP 503 → 直接 CSV API + manual analysis,112+113 年)
**Access status**: ok
**Pages/length**: 5 列 (申訴及調解程序 ×3 軸 + 合計 ×1 each year) × 27 欄

## Directly addresses
- Q6 (執法/申訴實況 — 第二縣市結構性零 confirmation): 桃園 schema 與新北 schema 結構性 finding 一致 — 全無 biometric/個資/隱私/inference category。
- Q4 (A∩D 灰區 institutional invisibility cross-locality): 結構性 invisibility 不是新北市單一現象,而是台灣 consumer complaint schema 的系統性現象。
- Q7 (政策建議): Schema 更新需求對應的不只一縣市,而是全國消保處共用框架的更新。

**Page/section**: CSV API direct dump verbatim (2026-05-27,113 年)
**Why it matters**: **桃園市 113 年 (2024) 全年 4,564 件 consumer complaint,分 25 個具名 category + "其他" + "合計"**。具名 category 全為傳統商品 (食品/房屋/車輛 / 醫療器材 / 化粧品 / 通訊及周邊產品 / etc),**未列「個資 / 隱私 / 生物特徵 / 自動化決策 / inference / AI / kiosk」任一細項**。「其他」一欄 823 件 (約 18% of total) — 同 c105 (新北市) residual bucket,所有「新類型」consumer harm 都被 absorbed 進此 opaque 池。**第二縣市重複驗證 Q6 結構性零的 schema-design 根源**。

**Page/section**: 112 + 113 年 CSV cross-year 分析
**Why it matters**: 桃園「其他」bucket 從 112 年 15.1% 升至 113 年 18.0% (one-year growth +2.9pp),**residual bucket 占比上升趨勢與 c105 (新北市) 同向**。對 Drafter:**「新類型 consumer complaint 快速出現但 schema 未跟上」此結構性問題在桃園也有資料支持**。Q6 / Q7 政策建議可指出:全國消保處應制定統一的「inference / 生物特徵蒐集」子類定義,讓各縣市同步加入 schema。

## Structural content worth knowing
- 桃園 dataset 涵蓋 109-113 年 (2020-2024) 5 年資料,113 年為最新版本 (2024 年)。
- 桃園 dataset 在 data.gov.tw 中的「資料服務分類」標為「生活安全及品質」— 與「個資 / 隱私」服務分類完全脫鉤,顯示**桃園消保處設計時未把 biometric / 個資投訴 framing 為「消費爭議」可能類型**;此 framing 缺席本身就是 Q6 / Q4 灰區證據。
- 桃園 dataset 與新北 dataset schema 細部不同 (桃園 25 個具名 + 其他,新北 16 個具名 + 兩個 residual buckets) — 桃園較細但仍無 biometric category;cross-locality 比對顯示「Schema 細緻度可以變,但 biometric 維度跨縣市一致缺席」 — 結構性不是技術問題、是 framing 共識問題。
- 「殯葬設施」「禮券」「殯儀館」這類細項都被 schema 顯式列出 — 表示 schema 設計對「特定 niche consumer harm」是有 capacity 添加 categories 的,**未添加 biometric/inference category 是設計者未把此議題列入優先,不是「無法 represent」**。

## Caveats / limitations
- 與 c105 相同 caveat:「結構性零」不等於「實質零」,「其他」buckets 中可能含 biometric 相關投訴但無法獨立辨識。
- 桃園與新北 schema 結構不對齊,意味跨縣市跨年聚合需要 schema mapping 工作;Drafter 不應 naive 加總跨縣市「其他」bucket 數字。
- 桃園 109-111 年資料未 deep-read (本 extract 聚焦 112-113 年);Drafter 若需更早期數據可請 operator 取得。
- 「申訴及調解程序」3 軸 (第一次申訴 / 消保官申訴 / 調解案件) 不是 3 個 disjoint sets — 同一案件可能在多階段都計數;Drafter 引用「合計」時要說明「跨階段彙總,不是 unique cases」。
