# 政府 IT 採購市場結構診斷（Government IT-Procurement Market Structure, TW）

姊妹研究：`gov-procurement-personality-tw`（全體政府採購人格類型學）。
本研究把鏡頭收窄到**資訊（IT）採購**，問一個結構問題：政府買 IT 的市場長什麼樣，
而這個結構如何解釋「數位轉型為何難前進、開源/公共程式為何進不來」。

## 定位（與 operator 確認）
不是替誰定罪，是**畫出政府 IT 採購市場的結構地圖**。四個可量化面向指向同一個結構：
集中（寡占）＋首都化（台北）＋低價/低品質導向＋鎖定既有廠商。
「數位轉型阻力／開源缺席」不是獨立薄弱框架，而是這四面向**綜合出來的結論**。

紀律鐵則（沿用姊妹研究）：限制性招標、廠商集中、重複得標都只是**結構訊號**，
採購法 §22 有合法事由（獨家、後續擴充、相容性、緊急）。任何「弊端/綁標」宣稱都需個案查核。
**訊號 ≠ 弊端**；看到集中就喊綁標＝把研究做歪。

## 資料源
`pcc-tender`（twinkle-hub MCP）：行政院公共工程委員會 政府電子採購網半月公開資料 row-level mirror。
決標公告 85,599 筆（2015-04→2026-09）。授權：政府網站資料開放宣告，註明出處。

## IT 母體定義（全研究統一，務必對齊）
```
announcement_type='決標公告'
AND procurement_attr IN ('財物類','勞務類')   ← 排除工程類（捷運號誌/電氣化等系統工程非本題）
AND title 命中 IT 關鍵字網：
   系統/軟體/資訊/資通/網站/平臺/平台/資料庫/雲端/伺服器/資安/電腦/數位/機房/網路/程式
```
- 規模：13,339 件，名目決標額 ~NT$379B（財物 6,431 件 / 勞務 6,908 件）。
- distinct 廠商 ~4,900、distinct 機關 ~?（財物 1,504 / 勞務 1,106 機關）。

### ⚠️ 已知資料品質坑（分析時務必處理）
1. **關鍵字網污染**：「系統」在財物/勞務仍混進重電/環保/醫療設備（中欣行脫硫 178 億、
   KC Cottrell、士林電機、西門子醫療、台灣飛利浦）。→ **以件數為主、金額為輔**判讀；
   金額型宣稱要先在本地把非 IT 大戶 tag 掉。
2. **覆蓋率不均**（坑見 pcc-tender-data-gotchas）：2022 件數暴增且含小額；跨年趨勢只對
   「標籤穩定」的指標做（未經公開評選 11 年同字串、可趨勢；總量/share 需條件化母體）。
3. **廠商名變體**：中華電信多分公司、精誠系三家、IBM 中英並列、資拓宏宇英文版 →
   實體層 + 集團層雙報。
4. **金額是名目字串**：`TRY_CAST(award_price AS BIGINT)`；`agency_id` 全 0 不可用。

## 四條線（threads）
### A. 系統整合商寡占（市場集中度）
- 量：top 廠商 by 件數（IT-robust）與金額；CR4/CR8/CR20、HHI；集團 roll-up。
- 點名寡頭：中華電信系 / 精誠系 / 神通 / 凌群 / 資拓宏宇 / 叡揚 / 關貿 / 工研院·資策會（法人）/ IBM…
- 守線：寡占≠違法；政府 IT 需大型 SI 整合能力，集中有供給面結構原因。

### B. 數位首都集中（廠商地理）
- 量：得標廠商登記地（bidder_addr 解析縣市）的金額/件數分布 → 台北佔比。
- 殺手題：**非台北機關**的 IT 決標，多少流向台北廠商（買方在地方、賣方在首都）。
- 守線：登記地≠履約地；大廠總部設台北。講「中標廠商首都化」而非「台北人壟斷」。

### C. 決標原則：品質導向的缺席（最低標 vs 最有利標）
- 修正後框架（基準驗證後）：IT 並非比全政府更殺低價；真正命題是
  **真·最有利標僅 3.3%（與全政府 2.9% 同樣稀少）**，IT 未因品質敏感獲得品質採購保護。
- 待驗：財物 vs 勞務拆分——客製系統建置（勞務）到底比價還是比優？決定本線保留/改寫/併入綜合。

### D. Vendor lock-in（鎖定）
- 量：未經公開評選 share（IT 10.5% vs 全體 6.6%，11 年趨勢）、重複機關×廠商配對
  （連續多年＋永遠 sole-source＝硬鎖定）、維運/授權 vs 建置/開發比（年金式支出）。
- 旗艦案例：中華郵政×IBM z/OS 十年連續未經公開評選（~33 億）、台電×微軟、臺鐵票務×中華電信。
- 守線：後續擴充/原廠維護有合法事由；高佔比是值得查的訊號，非違法證據。

## 綜合（synthesis）
四線交織 → 政府 IT 是封閉、集中、首都化、鎖定既有廠商、品質採購缺席的市場。
這個結構本身解釋了：開源/公共程式為何在採購語言裡「零存在」（標題零命中），
以及數位轉型為何難——錢綁在養既有系統、市場進入門檻把新／小／開源玩家擋在外面。

## 限制（先寫下，最後回頭核對）
- 抽樣非普查；只談相對結構樣態，不談絕對市佔/排名。
- 標題層分析：開源「零命中」是標題層，不代表規格書零要求（措辭須限定在標題層）。
- 廠商登記地非履約地；集團歸併為人工策展，可能有漏。
- 一切集中/鎖定訊號≠弊端，§22 有合法事由。
