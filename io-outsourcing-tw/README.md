# io-outsourcing-tw

**中國在數位威權業務上的公私協力實踐，讓民主國家的咎責顯得凌亂且無力**

對內是一門公開採購的生意；對外，被具名的至今只到承包商那一層。

---

## 這份研究在問什麼

威權國家不自己執行對外資訊操弄，而是發包給民間公司——輿情科技、公關公司、內容農場企業、帳號供應鏈，各有專門廠商。這篇文章處理三件事：

1. **這個承包市場實際長什麼樣**，從買方側（中國政府採購公告）與賣方側（企業登記還原）兩邊看。
2. **這種安排產生了什麼後果**——而不是主張它出於什麼動機。
3. **研究方法為什麼會撞到天花板**，以及防守方該把力氣移到哪裡。

## 主張的邊界

這是本研究最需要被理解的地方。

**主張的是功能性後果，不是動機。** 沒有任何證據說明中國為什麼選擇外包；被引用的廠商一手文件甚至指向反方向（廠商自籌資源把系統做出來，再向上推銷）。Ong、聶輝華與 Lee 以 3,243 份採購中標文件主張動機是能力擴充，本研究接受這個解釋。

**能主張的**：操作者有意隱藏資產之間的關聯（強）；這種隱藏有助規避平台執法、維持來源可信度（強）；外包增加了從操作者往上追到承包商的障礙（部分成立）。

**不主張的**：外包切斷了承包商與國家委託人之間的責任鏈（未充分證明）；國家選擇外包是為了規避咎責（沒有任何證據）。

完整的對話見 `pipeline/publication/appendix-counterevidence.md`。

## 研究軌

```
brief → collect(×2) → gate → segment → draft(v1–v8) → review(×4) → publication
```

| 目錄 | 內容 |
|---|---|
| `pipeline/publication/` | **對外發表稿**（主文＋兩份附錄） |
| `pipeline/draft/citation_map.md` | 每項主張 → 來源、證據層級、強度自評；含成稿過程更正紀錄 |
| `pipeline/reasoning_chain.md` | **十次「主張→反證→收窄」的完整紀錄** |
| `pipeline/collect/` | 候選來源與覆蓋率報告 |
| `pipeline/gate/` | 通過／拒絕的來源與理由（63 筆通過） |

## 這個專案值得複用的部分

**`reasoning_chain.md` 比稿件本身更有方法論價值。** 它記錄了十次收窄，每一次都朝同一個方向：主張變窄、證據變硬。而觸發修正的幾乎都是同一件事——**取得一手全文**。二手摘要在本專案造成六次錯誤。

`pipeline/brief_expanded.yaml` 的 `hard_rules` 區塊（22 條，未公開）也是一種可複用的做法：把「違反即算失敗」的紀律寫成機器可讀的規則，每一條都對應一個真的踩過的坑。

## 未公開的部分，以及為什麼

- **`pipeline/extracts/`（19 個逐字抽取檔）**——含大量來自付費專書與付費期刊的逐字引文。引用一段是合理使用，整份公開等於重製他人著作。查核功能由 `citation_map.md` 承擔（記載每項主張引自哪份文獻的哪一頁）。
- **83 頻道網絡的頻道名單**——樣本以演算法相似度建立、原分析自陳可能含誤判，且歸因空白。公布名單等於把「疑似協同操作」的標籤貼在一群無法被證明有關聯的帳號上。方法與統計摘要見 `pipeline/publication/appendix-method.md`。
- **`pipeline/brief*.{md,yaml}`、`pipeline/review/`、內部狀態檔**——含內部批評與對未公開材料的引用。
